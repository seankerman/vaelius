# PostgreSQL search permission projection

Migration 022 separates search authorization from the size of retained source history. Full `enterprise_dependencies` provenance remains authoritative and unchanged. The projection is a derivative in the same tenant PostgreSQL database, not another corpus.

`search_policies` deduplicates identical source restrictions, including tenant, owner, visibility, external project, source activity, connection identity and source-ACL freshness. `search_source_policies` maps sources to these policies. `search_document_policies` counts how many full-provenance dependencies require each policy. A document must satisfy every required policy. Combining inputs never unions their readers or drops uncited observer context. A missing mapping produces a denying policy, and a document with no requirements cannot pass.

Statement triggers update the projection within the same transaction as source, source revision, source ACL and dependency inserts, updates, deletes and truncations. The reverse dependency index supports source changes. Migration 023 replaces the original schema-wide advisory lock with ordered row locks on affected sources and ordered policy-count updates. Unrelated source updates can commit concurrently; shared inputs still serialize correctly. PostgreSQL can abort conflicting multi-row transactions as deadlocks, so callers must retain transaction rollback/retry semantics. A failed write rolls back both authority and projection. Old installed writers also execute these triggers. Direct privileged replication/restore operations must rebuild the derivative before releasing a restore hold.

Group membership, project state, connection readers/activity and permission expiry are evaluated live. The projection does not copy group membership into a user-by-document permission table. Existing service identity, delegation, generation, current revision, preference scope, reviewed release, observer invalidation and final delivery boundaries remain in place. Ordinary lexical/vector queries use document-indexed requirements before their result limits, without an `authorized_docs` materialization or traversal of raw provenance. The old `legacy`, `anti_join` and `authorized_cte` predicates remain internal diagnostic oracles for frozen comparisons. Saved runtime settings using those names are accepted for compatibility but normalize to `compiled`; a serving configuration cannot select the old paths. Code rollback uses a preserved older installed package.

The logical recovery helper excludes these three derivative tables from snapshots and reconstructs them from restored authoritative records while the target remains held. `search_rebuild_permissions()` is an explicit maintenance operation. It blocks authoritative writes while rebuilding; it is never a serving startup or per-query operation. `agenthub.search_permissions.inspect_projection(db)` performs a full one-snapshot consistency audit and returns counts only. Run audits deliberately, not on every request.

## Restricted search transactions and delivery

Migration 024 adds a narrow, schema-bound `SECURITY DEFINER` permission function. Migration 025 additionally limits revision, FTS and vector rows to the document's active revision: current document grants must not expose older content when a query omits its revision join. Explicit operator provisioning creates one deterministic `NOLOGIN`, `NOBYPASSRLS`, `NOINHERIT` reader role per database/schema/worker. It grants SELECT on the search content relations and vector-state metadata, with row-level policies on documents, revisions, FTS rows, and vectors. The independent worker policy retains canonical write access. The migration owner is trusted; the serving reader is neither the owner nor a bypass role.

The service authenticates the current actor and delegation before switching the transaction to the reader role. Request context is transaction-local and cleared on success or rollback. Missing context denies all search content. Raw sources, credentials and observer transcripts are not readable by this role. This protects against an accidentally omitted search filter; it does not grant customers a SQL interface or isolate data from the trusted database/service operator. Original-document, historical evidence and other non-search endpoints retain their canonical authorization paths.

The indexed all-requirements aggregate also denies orphan documents and missing policies; it replaces the old separate existence semi-join that repeatedly scanned the compact requirement table. The selected-card author lookup uses the same compact projection rather than rereading source history. Current membership, source/connection freshness and all-input restrictions still apply.

For HTTP search, ranking uses MVCC without a delivery lock. Only final identity, revision and authorization validation takes a shared reader lock; revocations use the matching exclusive boundary. Concurrent readers overlap, and a revocation committed after ranking removes the card before delivery. Historical cards retain their separate temporal authorization semantics. This defines a delivery authorization checkpoint, not a promise to retract bytes already sent.

PostgreSQL disallows `COPY FROM` on RLS-protected tables. The synthetic bulk harness now copies to a temporary transaction-local staging table, then performs ordinary `INSERT ... SELECT`, so policies and statement triggers execute normally. No bypass privilege is granted.

## Local operations

Build and install independent pinned wheels before using the new mode. Apply `agenthub.postgres.migrate(admin_dsn, statement_timeout_ms=120000)` and the existing role grants for every active tenant routed by the installed service. The configurable migration deadline does not change ordinary 15-second query deadlines. The root workspace's `tools/measure_indexed_permissions.py --operation migrate --tenant TENANT` performs this against an existing tenant in the explicitly supplied local profile and records a receipt; it creates no tenant. Startup never applies migrations automatically. Check `/ready` as well as `/health` after the rollout.

Use the compiled path in the private runtime settings, preserving other settings, and restart the owned isolated API. Verify its build through `/health` and use authenticated requests to test delivery. The historical authority's migration and original dependencies are retained on rollback: restore the saved settings with `authorized_cte` and restart the previous installed code. Do not drop the migration or alter applied checksums. Previous-code writes continue to maintain the projection for a later roll-forward.

## Scope of evidence

Synthetic tests compare full authorized sets and ranked revision IDs with the previous predicate. They cover mixed restrictions, membership, expiry, connection readers, private preferences, current generation, delegation/release, correction/withdrawal, transaction rollback, missing projection repair, concurrent writers, truncation and revocation between ranking and delivery. The existing recovery and observer suites continue to run.

Twenty thousand identical-policy sources require one document policy in the regression fixture. The historical corpus is separately audited and measured using existing development questions; no semantic confirmation set is consumed. See the superproject's `docs/evidence/indexed-permissions-v2/STATUS.md` for installed-build receipts, timing sample sizes and HTTP evidence.

This removes dependence on raw provenance volume for ordinary search authorization. It does not promise constant-time search, unlimited policy diversity, high enterprise ingestion throughput or production cloud readiness. Exact vector ranking still examines candidate vectors. Many genuinely different input policies require more checks. Policy changes still coordinate with a short shared delivery checkpoint. Search ranking and embedding run outside that lock. Other authorized read endpoints use shared reader locks; mutation methods retain their exclusive delivery boundary. This is not a throughput claim for an unbounded ingestion workload. Curation, ranking scores and answer-selection behavior are unchanged.
